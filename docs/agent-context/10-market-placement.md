# 10 — Маркет: владелец, размещение карточек, платный доступ

> Продолжение [09-themed-sites.md](./09-themed-sites.md). Всё живёт в **mega-hub** (`hub.*`). **Vitrina не трогаем.**

## Роли

| Роль | Кто | Что может |
|------|-----|-----------|
| **Владелец маркета** | блогер, гид, ассоциация, DMC, сам тенант | настраивает дизайн и наполнение, тарифы, одобряет заявки, видит деньги |
| Редактор | нанятый контентщик | страницы, блоки, журнал; **не** тарифы и не заявки |
| Модератор | помощник | одобрить/отклонить заявку, скрыть карточку |
| Тенант | компания из Vitrina | просит разместить свои карточки, платит, видит статистику |
| Platform admin | мы | создаёт маркет, назначает владельца, ставит комиссию платформы |

Владелец **не** platform admin. Поэтому нужна таблица `hub.site_members` — без неё блогер не сможет управлять своим маркетом.

## Два направления подключения

Одного мало, нужны оба:

1. **Тенант просит** — заявка из кабинета Vitrina или с публичной страницы маркета → владелец одобряет → карточка появляется.
2. **Владелец приглашает** — блогер сам собирает состав. Без этого новый маркет стартует пустым, и продавать нечего.

## Единица оплаты — карточка

«Одна карточка = столько-то в месяц» → платим за **конкретную карточку**, не за компанию.

```
hub.site_placements — одна строка = одна карточка в этом маркете
  listing_id IS NOT NULL  → карточка услуги
  listing_id IS NULL      → карточка компании
  paid_until              → до какой даты висит
  slot                    → standard | featured | pinned
```

## Режим наполнения

| Режим | Кто попадает на страницу | Для кого |
|-------|--------------------------|----------|
| `scope` | все по гео/теме автоматически | демо, бесплатные витрины |
| `approved` | **только** одобренные размещения | платный маркет блогера |
| `mixed` | scope + оплаченные выше в сортировке | переходный |

Без `approved` платная модель не работает: карточки затекали бы бесплатно по scope.

## Модели денег

Подписки может быть недостаточно, закладываем сразу:

| Модель | Как | Кому подходит |
|--------|-----|---------------|
| `free` | бесплатно, только модерация | старт маркета, наполнение |
| `monthly` | цена за карточку в месяц | понятно тенанту, предсказуемо владельцу |
| `commission` | % с брони, пришедшей из маркета | блогеру выгоднее на сильном трафике |
| `hybrid` | небольшая база + % | зрелый маркет |

Атрибуция брони **уже есть** в Vitrina (`submissions.source_type='marketplace'` + marketplace-поля). Для `commission` переиспользуем её, новый контур не строим.

## Деньги: кто собирает

Платформа биллит тенанта → выплата владельцу минус `platform_fee_percent`. Так проще юридически и не заставляет блогера самому выставлять счёта.

Нужны: `site_invoices`, `paid_until`, grace-период, авто-скрытие после неоплаты, реквизиты выплаты владельцу.

## Что часто забывают (и мы закладываем)

1. **Статистика тенанту.** Показы, клики, переходы на бронь по каждой карточке. Без цифр второй месяц не оплатят — это главный фактор продления.
2. **Позиция как товар.** Продаётся не только факт размещения, но и место: `featured` / `pinned` + `sort_weight`. Основной апселл блогера.
3. **Grace-период.** Оплата опоздала — карточка не должна исчезать мгновенно.
4. **Причина отказа.** Тенант должен понять, что исправить, иначе поток заявок умирает.
5. **Ручные карточки + claim.** Блогер добавляет объект, которого нет в Vitrina (озеро, перевал, кафе). Потом владелец объекта регистрируется и **забирает карточку себе**. Маркет наполняется до появления тенантов и сам приводит их на платформу — это канал роста, не просто контент.
6. **Публичная страница «разместиться».** Блок с тарифами + форма. Иначе блогеру некуда вести тенантов из своих сторис.
7. **Оферта.** Принятие условий маркета в момент заявки (`accepted_terms_at`).
8. **Лимиты.** Максимум карточек на тенанта, проверка домена, уникальность slug — иначе один тенант забьёт всю выдачу.
9. **Уведомления.** Заявка, решение, «оплата через 3 дня», «карточка скрыта».
10. **SEO и UTM.** Блогер живёт трафиком: meta/OG на маркет, sitemap, метки источника.
11. **Языки.** Для Каракола сразу RU / EN / KY.

## Фазы

| Фаза | Что | Статус |
|------|-----|--------|
| **S1** | `hub.sites` + конструктор + публичная страница + ассистент | черновик кода |
| **S2** | Владельцы (`site_members`), режим `approved`, заявки, ручные карточки, тарифы-витрина | схема + демо готовы |
| **S3** | Счета, `paid_until`, grace, авто-скрытие, статистика карточек | схема заложена, UI нет |
| **S4** | Комиссия с брони, выплаты владельцу, claim ручной карточки | только схема/план |
